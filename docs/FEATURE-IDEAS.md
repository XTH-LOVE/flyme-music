# 功能建议：对比市面音乐软件

盘点现有：13 个页面、6 个音源（网易云/QQ/酷我/JOOX/B站/Hi歌）、本地音乐 + 标签解析 + **音频特征分析**、AI 伴听、一起听、歌单导入、听歌统计。

结论先说：**你的功能面已经比多数同类开源播放器宽。** 所以下面按「数据已经在手，只差一层皮」到「要新造基础设施」排序，并且**明确列出不该做的**。

---

## 一、最该做的三件：数据已在手，只差一层皮

### 1. 年度听歌报告（强烈推荐）

网易云年度报告、Spotify Wrapped 是**全年传播量最大的功能**，而你的 `playLog` 里数据全都有。

要展示的东西都在：
- 听得最多的一首 / 一位歌手 / 一张专辑
- 第一次听某首歌是什么时候（`playLog` 有 `ts`）
- 深夜时段听了多少（`ts` 可算小时分布）
- 单曲循环最多的一首（同 key 出现次数）
- 「今年你听了 N 首歌，共 M 小时」

**为什么值得做**：它是**唯一一个用户会主动截图分享**的功能。而且成本极低 —— 数据、图表能力、分享卡片你都有。

**建议**：不只在年底，做成「最近 30 天 / 今年 / 全部」三档，随时可看。

### 2. 睡眠定时器

所有主流音乐软件都有，而你没有。**这是最便宜的"完整度"提升。**

- 定时 N 分钟后停止 / 播完当前专辑后停止
- 最后 30 秒音量渐弱（比硬切舒服得多）
- 放在播放页的更多菜单里

**成本**：一个定时器 + 一个音量淡出循环。**半小时的事。**

### 3. 均衡器

你有 **Web Audio 管线**（音频特征分析已经在跑），加 `BiquadFilterNode` 就是现成的。

- 10 段图形均衡器 + 几组预设（流行/摇滚/人声/低音增强）
- 最好加**响度均衡**（ReplayGain / 音量归一化）—— 这个比 EQ 更实用：不同音源的音量差异很大，跨音源播放时忽大忽小是真实痛点

**为什么推荐响度均衡**：多音源播放器的**特有问题**，主流单源 App 不需要解决。这是你能做得比它们好的地方。

---

## 二、值得做，但要新造东西

### 4. 桌面歌词 / 状态栏歌词

网易云和 QQ 音乐的核心卖点之一，Halcyon 也有（`DesktopLyricService.kt`，1088 行）。

**Android 侧需要**：`SYSTEM_ALERT_WINDOW` 权限 + 一个悬浮窗 Service。**可以参照 Halcyon 的思路，但不能照抄代码**（它是原生 Compose，你是 WebView）。

**成本**：中高，且需要真机反复调试。**建议排在年度报告和睡眠定时器之后。**

### 5. 歌单迁移（跨平台导入）

你已经有 `playlistImport.ts`。**把它扩成「从网易云/QQ 迁移歌单」**：

- 用户贴一个歌单链接或 ID
- 应用逐首在其他音源里搜索匹配
- 生成一个本地歌单，标出没匹配上的

**为什么有价值**：**这是"想换 App 的人"最痛的一步。** 一个用网易云五年的人有几百首歌单，迁移成本是他不换 App 的最大理由。解决这个，你就有了一个真实的拉新点。

**成本**：中。搜索接口已有，主要工作是匹配与容错（同名不同版本、翻唱、live）。

### 6. 音乐标签编辑

你有 `lofty` 做**读取**，Halcyon 有 `TagEditorLauncher.kt`。

- 批量编辑本地文件的标题/歌手/专辑/封面
- 从在线音源**回填**缺失的标签和封面

**为什么值得**：本地音乐用户（尤其从各处下载的）标签混乱是常态，而**这是纯本地操作、不涉及版权、不依赖第三方接口**的功能。

## 三、我建议**不要做**的

### ✗ 播客 / 有声书 / 相声

**这是另一个内容垂直领域**，不是播放器功能。需要独立的目录、订阅、进度同步、推荐体系。做半套比不做更糟 —— 用户会试一次然后发现内容贫乏，反而降低对整体的评价。

### ✗ 社交：关注 / 粉丝 / 动态 / 评论 / 弹幕

**需要后端 + 内容审核 + 举报机制**，是一个长期运营负担，不是功能开发。

而且评论区的价值来自**内容生态**（网易云评论能火是因为用户量），个人项目做这个只会得到一个空评论区 —— **空评论区比没有评论区更劝退**。

### ✗ MV / 视频

**会把音乐播放器变成视频 App**，而视频的分发、版权、播放器体验是完全另一套。你的 B 站音源已经能拿到音频，足够了。

### ✗ 听歌识曲

技术上需要**音频指纹库**（AcoustID/Shazam 级），要么依赖第三方付费接口，要么自建（不现实）。**投入产出比最差的一项。**

## 四、比功能更重要的一件事

**跨设备同步。**

你现在**收藏、歌单、历史全部只存在本机**（隐私政策里就是这么写的，也是这么实现的）。这意味着：

- 换手机 = 全部丢失
- 网页版和 APK 是两个独立的世界

主流 App 全部云端同步，**而这是"个人项目"和"日常在用"之间最大的差别** —— 一个你不敢把五年歌单放进去的播放器，就永远只是玩具。

你已经有 Supabase（一起听在用）。**把收藏/歌单/历史同步上去，是投入产出比最高的一项"基础设施"**，虽然它不像新功能那样看得见。

**建议**：如果只做一件事，做这个。它不会让人截图分享，但会让人真正开始用它。

---

## 建议顺序

| 顺序 | 项 | 理由 |
|---|---|---|
| 1 | **睡眠定时器** | 半小时的事，立刻补上"不完整"的感觉 |
| 2 | **年度听歌报告** | 数据已在手，唯一会被主动分享的功能 |
| 3 | **响度均衡 + 均衡器** | 多音源播放器的真实痛点，你比主流 App 更有理由做 |
| 4 | **跨设备同步** | 不显眼，但决定它是不是"能日常用" |
| 5 | 歌单迁移 | 真实的拉新点 |
| 6 | 标签编辑 | 纯本地，无外部依赖 |
| 7 | 桌面歌词 | 成本最高，需要真机反复调 |

---

## 最后一句

**功能数量不是瓶颈，可靠性才是。**

今天一天修了 8 个 bug，其中 6 个是「网页版正常、打包版失效」的静默失败。**在这个状态下加新功能，只是把不可靠的表面积扩大。**

建议先把已发版的东西在真机上跑通（通知栏播放器、后台播放、AI、歌词），再往上加。
